# Техническое SEO версии согласования

1. Каждая HTML-страница содержит один H1, Title, Description, canonical, Open Graph и meta robots noindex,nofollow. В SEO-паспорте показаны фактически выведенные значения.
2. Canonical в Pages-сборке указывает на https://samfinstat.github.io/rossantoakru/ и соответствующий путь. Не сообщаем поисковой системе, что новые страницы уже существуют на рабочем домене.
3. Сохранены исходные пути категорий и товаров. Кириллические адреса записываются как Unicode-имена файлов, href корректно кодируется; кодированные и декодированные варианты проходят проверку. Две крышки имеют отдельные страницы прежнего адреса с canonical на основную карточку; HTTP 301 на GitHub Pages не имитируется.
4. Product содержит название, описание, бренд, URL и доступное фото. Offer, цены, рейтинги и отзывы не выдумываются. Категории используют CollectionPage, статьи — Article. Хлебные крошки и Organization заполняются отдельно.
5. Изображения обслуживаются из assets/products, имеют alt, размеры и ленивую загрузку в списке. Проверка URL картинок включена в общий прогон.
6. На project Pages robots.txt внутри /rossantoakru/ не управляет хостом. Закрытие обеспечивается meta robots; публикация остаётся публичной. sitemap для индексации пока отсутствует намеренно.
7. Для production необходимы другой origin, проверенные канонические адреса, серверные 301, корректный статус 404, XML-карта только индексируемых страниц и настройка robots в корне рабочего хоста. Нельзя просто удалить noindex и считать запуск завершённым.
8. Семантика остаётся предварительной. В data/source/topvisor.csv регион не указан. Метрики сохраняются без заполнения пропусков. Неоднозначность отражена в статусах review/informational/exclude.
9. После запуска подключить Яндекс Вебмастер/Google Search Console, наблюдать HTTP, canonical, дубли и индексацию. Заявки и качество трафика сверять с CRM, а не только с нажатиями кнопок.
10. Формы до подключения серверной части только готовят письмо. Ключи Bitrix24 должны оставаться на сервере; контроль доставки, повторов и спама обязателен при реализации интеграции.

Методологические источники: https://developers.google.com/search/docs/crawling-indexing/canonicalization-troubleshooting и https://developers.google.com/search/docs/crawling-indexing/block-indexing.


## Паспорт на каждой странице

Кнопка «SEO страницы» открывает индивидуальный рабочий паспорт. Краткий HTML-паспорт внизу остаётся резервным вариантом при недоступном JavaScript. Полная панель сравнивает DOM открытой страницы со снимком последней сборки в `assets/seo-passports-*.json`. «HTML совпадает» означает только совпадение значения; это не SEO-оценка и не подтверждение индексации. Отсутствующий OG image показан как «Не задано», с предложенным файлом для внедрения.

Для каждого URL отдельно указаны тип, Title, Description, H1, canonical предпросмотра и плановый canonical рабочего домена, robots, OG, типы JSON-LD, H2/H3, изображения и ALT. Раздел «Техническое задание» содержит требования к HTTP, sitemap, корневому robots.txt, дубликатам, редиректам, параметрам URL, перелинковке и проверке после запуска. Для товаров добавлены происхождение контента, состояние фото и требования к Product; для разделов — структура, интент и состав каталога.

Рабочий домен в плане — `https://rossantpack.ru`. Это план миграции, а не утверждение о существовании нового пути на production. Служебные страницы, 404 и прежние адреса исключены из плана индексируемой XML-карты. У прежних адресов целевое поведение — серверный 301; meta noindex не является его заменой.

Запросы и все пять частотностей читаются из исходной карты без обрезки списка и подстановки нулей. Если запросы назначены родительскому разделу, они показаны отдельно как контекст; карточка не получает это назначение автоматически. Регион, период замера, соответствие интенту и пересечения кластеров требуют проверки.

HTML-данные проверяются локально при открытии окна, серверные HTTP-заголовки, редиректы, реальная индексация и Core Web Vitals — отдельные задачи, в интерфейсе не помечаются выполненными.
