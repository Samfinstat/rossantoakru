# Подготовка миграции

Рабочий домен не переключён. GitHub Pages служит для согласования.

- Исходные пути из доступного каталога сохранены. Не менять URL по эстетическим причинам.
- data/url-aliases.json фиксирует две пары адресов крышек из CSV и старого сайта. В preview старые адреса открываются как страницы перехода с canonical на основную карточку; это не серверный 301.
- Два раздела пластиковых ложементов сохранены по исходному заданию. Их тексты ориентированы на комплектацию и технологию, основной предварительный кластер закреплён за /product/lozhementy/lozhementy-iz-plastika1/. Перед production сравнить выдачу, позиции, органический трафик и фактический ассортимент. Не включать 301 автоматически.
- До смены хостинга выгрузить полный список URL из CMS, sitemap, аналитики, Вебмастера и обратных ссылок. Сопоставить с docs/site_tree.csv; неизвестные адреса не перенаправлять массово на главную.
- Для каждой пары адресов указать действие: сохранить 200, релевантный 301, 410/404 при удалении. После внедрения проверить отсутствие цепочек и петель.
- До миграции устранить ошибку TSolution\Basket рабочего Битрикса и повторно проверить HTTP-статусы. Наличие HTML в ответе 500 не делает страницу исправной.
- Подтвердить форму, CRM, реквизиты, политику обработки данных, аналитику, canonical, robots и sitemap на рабочем домене. Только после этого открывать индексацию.
